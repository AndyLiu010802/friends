# 全局指挥台(好友搜索)— 设计文档

日期:2026-07-27
来源:对话内头脑风暴,用户批准方向。

## 背景与总体路线

用户愿景:通过日常积累对朋友"了如指掌"(读心术)。核心飞轮:**记得越顺手 → 积累越厚 →
AI 越懂 → 提醒越准**。拆四期落地,本文档只覆盖第一期:

1. **第一期·查找更高效(本期)**:全局指挥台——3 秒内找到任何一个朋友。
2. 第二期·记录更快捷:全局"快速记一笔",选人复用本期搜索。
3. 第三期·主动提醒:生日 /「很久没联系」/ 关系目标偏离,做成首页信号流
   (`birthdayStatus`、`friendEnergy` 已有雏形)。
4. 第四期·移动端体验:PWA 安装 + 触控打磨。

已比较三个方案:A 全局指挥台浮层(选定)、B 独立列表视图(其核心价值被 A 的空查询
状态覆盖,不单做)、C 星图内高亮过滤(移动端操作慢、其他页面用不上,放弃)。

## 范围

纯客户端实现,不动数据结构、不加依赖。两个新模块 + 两处接入:

- 新增 `lib/friendSearch.ts`:匹配与排序纯函数(配单测)。
- 新增 `components/SearchOverlay.tsx`:搜索浮层 UI(配组件测试)。
- 接入首页(飞星动线)与好友详情页(路由跳转)。设置页、新建页本期不接。

## 交互设计

**唤起**:

- 桌面:`Ctrl+K` / `Cmd+K` 全局快捷键(浮层组件挂载的页面内生效),另在顶部导航
  加「⌕ 寻星」按钮(样式同「✦ 新纪录」胶囊按钮)。
- 移动:同一个导航按钮;浮层近全屏展示,打开即聚焦输入框。
- 输入框聚焦在 input/textarea 时快捷键不劫持(避免打字时误触发)。

**浮层内容**:

- 空查询:列出全部好友——`important` 置顶,其余按最近互动倒序(取最新
  `memory.date`,无回忆则用 `updatedAt`)。每行:星色圆点(`starConfig.coreColor`)
  + 名字 + 昵称 + 最近互动日期(如「3 天前」,复用 `dateUtils`)。
- 有查询:按下方匹配规则过滤排序;非名字命中的行附一条命中原因
  (如「喜欢:火锅」)。
- 键盘:`↑`/`↓` 移动高亮,`Enter` 确认,`Esc` 关闭;点击遮罩关闭;移动端点行即选。
- 无好友:「你的宇宙还空着」+「✦ 新纪录」链接;有好友但无匹配:「没有找到」
  + 同样的新纪录链接。

**选中后**:

- 首页:走 `InsightPanel.onSelectFriend` 同款动线——`setSelectedFriendId(id)` +
  `setFocusedFriendId(id)`,相机飞向那颗星并停靠卡片,浮层关闭。
- 好友详情页:`router.push('/friend/' + id)`,浮层关闭。

## 匹配与排序(`lib/friendSearch.ts`)

```
searchFriends(friends: Friend[], query: string): SearchResult[]
// SearchResult = { friend, matchField?: 'name'|'nickname'|'like'|'dislike'|'hobby'|'tag', matchText?: string }
```

- 查询先 trim、小写归一;空查询走上文的默认排序。
- 匹配字段与优先级:名字前缀 > 名字包含 > 昵称包含 > 喜好/雷区/爱好包含 >
  回忆标签包含(遍历 `memories[].tags` 去重)。同级内按最近互动倒序。
- 中文直接子串匹配,不引入拼音库(YAGNI;输入法打中文即可命中)。

## 错误处理

浮层只读 `getFriends()` 的本地数据,无网络请求、无失败路径;好友列表为空即显示
空状态,不抛错。
